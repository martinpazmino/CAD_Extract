# 19 App v2: from the PDF to the Baugrundmodell in Streamlit

> [!NOTE]
> **Superseded** by the step app of [21](21_app_schritte_normen.md) (FastAPI + web page,
> `python -m server`). This note stays as history; the Streamlit page of the Baugrundmodell no
> longer exists (Streamlit remains only for Excel v1). Projects saved by this version are picked up
> when the same PDF is opened.

The local app joins everything built so far: **the Gutachten PDF is uploaded, the Bohrungen are
recognised, they are reviewed and the Baugrundmodell is generated by itself** and shown in the That
Open viewer, on the same page. v1 (Excel following the template, Hamburg layout) stays as a second
page.

```
PDF(s) ──► extraction v4 (docs/17) ──► table of Bohrungen: review / correct ──► modeler (docs/18)
                                                                                  │
            That Open viewer (component) ◄── IFC 4.3 ◄────────────────────────────┘ ──► export
```

![App v2 with the Talheim example: warnings, check chips and viewer with the schematic row](img/19_app_talheim.jpg)

## 1. Starting

| System | How |
|---|---|
| Windows | double click on [`start.bat`](../start.bat): the first time it creates `.venv` and installs `requirements.txt` (+ OCR if possible), then it opens `http://localhost:8501` |
| Any | `pip install -r requirements.txt` (and optionally `-r requirements-ocr.txt`), `streamlit run app.py` |

No Node needed: the compiled viewer is in the repo ([`apps/web/dist`](../apps/web/README.md)). Only
whoever changes the viewer needs `npm install && npm run build` and to push the new `dist`.

## 2. The *Baugrundmodell* page

> [!NOTE]
> Since [20](20_lage_pruefung_viewer.md) the order is different: **tables first** (Bohrungen,
> Schichten, Lage & Unterlage), Bohrungen already visible in the viewer, a *Baugrundmodell
> erzeugen* button, then the model follows every change by itself; Prüfstand with *Einchecken*;
> Lage on the PDF of the plan; project state saved automatically. What follows is the first version.

1. **Input** (sidebar): one or several PDFs, or an [example](../data/beispiele/README.md)
   (georeferenced Berlin, Talheim without coordinates, synthetic demo, synthetic PDF).
2. **Extraction** with a progress bar per page and page class (vector / raster / OCR). The result is
   saved on disk by the `sha256` of the PDF, the OCR option and the extractor fingerprint: opening the
   same PDF again is instant; changing the extractor invalidates the cache.
3. **Indicators**: Bohrungen, Schichten (and how many to review: confidence < 0.6 or with a warning),
   with coordinates, with GOK, with Grundwasser.
4. **Model + viewer** at the top, always visible; check chips (Einheiten, Bohrungen in the model,
   Lage, deviation at the Bohrungen, closed solids, outside the model) and warnings about what was
   assumed.
5. **Tabs**: *Bohrungen* (editable table: include, GOK, Rechts-/Hochwert, EPSG; Lageplan),
   *Schichten* (logs of all Bohrungen in m NHN or depth, detail with the original description,
   confidence and source), *Modelleinheiten* (table and **Einheiten editor** → recompute),
   *Prüfbericht* (excluded ones with the reason, matrix Einheit × Bohrung ✓ / – / ?, warnings,
   parameters), *Export* (IFC, report, Einheiten template, extraction JSON and input JSON with
   corrections).

## 3. What is assumed and how it is marked

| Case | Default | Mark |
|---|---|---|
| No Bohrung with coordinates | **schematic row** (ordered by code, 20 m) — only if *no* Bohrung has coordinates | `coord_source = schematisch`; warning in the app, `Lage` in the IFC, `Lagebezug: lokal` in the model |
| Coordinates typed into the table | they are used; empty EPSG = local system | `coord_source = manuell` |
| No Bohrung with a GOK | GOK = 0 m (relative heights) | `gok_source = relativ`; `Hoehe` in the IFC |
| Some without GOK / without coordinates | they stay out | combined reason («keine Koordinaten, Ansatzhoehe (GOK) unbekannt») in the report, IFC and viewer |
| Same code in two documents | the second one unticked | «doppelt (auch in …)» |
| Bohrung unticked | out | «abgewaehlt» |

Project rule: a doubtful value is marked, never hidden. A schematic model is useful to see the
sequence, not to measure distances: the app says so in three places.

## 4. Correlation with strong relief

With Talheim (GOK from 749 to 772 m) correlation by absolute elevation gave **15 Einheiten**
(Schwarzdecke 1–3, Auffüllung 1–4…): the shallow Schichten follow the terrain. The matching cost is
now the **smaller of the distance in NHN elevation and in depth below GOK**: 15 → **6 Einheiten**
(Mutterboden, Schwarzdecke, Auffüllung, Schluff, Fels…). The synthetic cases give exactly the same
figures as in [18 §6](18_layer_modeler.md#6-results) and Berlin the same Einheiten as before the
change.

## 5. Pieces

| File | What it does |
|---|---|
| [`app.py`](../app.py) | Entry point: navigation between *Baugrundmodell* and *Excel nach Vorlage (v1)* |
| `ui/baugrundmodell.py` (removed, see [21](21_app_schritte_normen.md)) | v2 page |
| [`ui/pipeline.py`](../ui/pipeline.py) | No UI: extraction with progress and cache, model (`modell_bauen`, `ifc_bytes`), image of the plan |
| [`ui/projekt.py`](../ui/projekt.py) | Project state: corrections, Reihe, Lage, viewer events, Prüfstand ([20](20_lage_pruefung_viewer.md)) |
| `ui/viewer.py` (removed, see [21](21_app_schritte_normen.md)) | Streamlit component with `apps/web/dist`; the IFC is written as `modelle/<hash>.ifc` and passed by URL |
| [`ui/excel_v1.py`](../ui/excel_v1.py) | v1 page without functional changes |
| [`tests/test_app_pipeline.py`](../tests/test_app_pipeline.py) | 15 tests of the app layer (since [20](20_lage_pruefung_viewer.md)) |
| [`scripts/check_app.mjs`](../scripts/check_app.mjs) | End-to-end test in Chromium (examples or `--pdf`) |

Technical decisions:

- **Viewer as a component** (`components.declare_component(path=dist)`): same code as the standalone
  viewer; protocol `streamlit:componentReady` / `streamlit:render` / `streamlit:setFrameHeight`
  implemented by hand (without `streamlit-component-lib`). The IFC does not travel through the
  websocket on every rerun: it is written with name = hash and the viewer only reloads if the URL
  changes.
- **MIME types** registered in the app (`.js`, `.mjs`, `.wasm`): Streamlit takes them from
  `mimetypes` and on Windows the registry can return `text/plain`, which blocks modules and workers.
- **Progress without touching the extractor**: the module's `primitives()` is wrapped at runtime;
  `prototyp_v4.py` remains the regression reference (docs/17), unchanged.
- **Fragments worker** served by Vite (`@thatopen/fragments/worker?url`), WASM in `vendor/`: no
  unpkg.

## 6. Verification

- `pytest tests` (app, 6) and `pytest services/modeler/tests` (modeler, 31): green (today 15 and 36,
  [20 §9](20_lage_pruefung_viewer.md#9-verification)).

  all four, no page or server errors.
- Tested on Linux (container). **Windows is not tested here**: `start.bat` and the MIME registry are
  the part to watch at the first start.

## 7. Limits and next steps

1. Extraction with OCR takes time (Berlin 16 s with the OCR cache, Wachenroth ~5 min the first time):
   a background worker (architecture §4) would avoid blocking the page.
2. ~~Without coordinates there is only the schematic row~~ → own distances in the row and Bohrungen
   placed by hand on the Lageplan or the Längsschnitt PDF ([20](20_lage_pruefung_viewer.md)); reading
   them automatically is still pending (docs/07).
3. Click in the viewer → page of the PDF with the box of the Schicht (visual provenance).
4. Store projects (Supabase, docs/ARCHITECTURE §5) instead of only downloads: today the state is
   saved on the local disk ([20 §5](20_lage_pruefung_viewer.md#5-tables-before-the-model-erzeugen-and-nachführen)).
