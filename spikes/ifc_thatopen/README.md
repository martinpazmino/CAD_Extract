# Spike: geotechnical IFC 4.3 in That Open

Checks that a Baugrundmodell exported with IfcOpenShell (`IfcBorehole`, `IfcGeomodel`,
`IfcGeotechnicalStratum`, georeferenced EPSG:25832) can be loaded in That Open Engine.

| File | What it does |
|---|---|
| [`baugrund_ifc_spike.py`](baugrund_ifc_spike.py) | Generates the IFC4X3 (3 Bohrungen, layer-cake model with IDW) |
| [`thatopen_import_spike.mjs`](thatopen_import_spike.mjs) | Imports it with `web-ifc` and with the `IfcImporter` of `@thatopen/fragments` |
| [`export_ifc.py`](export_ifc.py) | **Real data:** canonical JSON of the extraction → IFC4X3 (`IfcBorehole` + strata with provenance and confidence; georeferenced if there is a CRS). Uses the writer of [`services/modeler`](../../services/modeler/README.md); the layer model (N3) is generated by `python -m baugrundmodell` |
| [`package.json`](package.json) | Pinned versions (fragments 3.6.0, web-ifc 0.0.78) |

```bash
pip install ifcopenshell numpy && python baugrund_ifc_spike.py baugrund_spike.ifc
npm install && npm run spike
```

**With real data (2026-10-26):** Berlin V-67b-VE (raster + OCR) → 7 Bohrungen, 80 strata, 5 in
EPSG:25833 → 0 schema errors → That Open: 80 elements with geometry. An empty Pset is invalid IFC: the
exporter only creates `Pset_BoreholeCommon` if there is a Grundwasser level.

**Result (synthetic):** the IFC validates without schema errors; `web-ifc` generates meshes for the 16
strata; the `IfcImporter` **discards them by default** and imports them once the geotechnical classes
are added to `importer.classes.elements`. Details:
[architecture §8.2](../../docs/ARCHITECTURE_BAUGRUNDMODELL.md#82-spike-results-verified).
